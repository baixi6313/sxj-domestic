## 0. 定位与边界（先说清楚是什么、不是什么）

**红队 = 经创始人授权的对抗验证实验室，不是"反 SXJ"。**

- 它的全部存在目的，是**主动尝试攻破 SXJ**，从而证明或提升协议的鲁棒性。
- 它与 SXJ 自身哲学完全一致：SXJ 主张"让现实验证 SXJ""创始人最终退出"，红队就是把"外部对抗性验证"**制度化、常态化**。
- 它直接补齐 ChatGPT 评审（2026-08-25）指出的工程缺口：证据来源真实性、数据结构可篡改性、裁定者中心化。

**红线（红队自身也必须遵守）：**

1. 所有测试只在**隔离副本 / 本地只读快照**上执行，绝不操作生产数据、公示墙、线上站点。
2. 发现漏洞后：**先记 Gzz-E 事件 → 报创始人裁定 → 等"执行"授权**，绝不"顺手改生产"（这本身就是越权，按 Gzz-H-SXJ-007 记 Gzz-C）。
3. 红队模拟的攻击行为属**授权测试**，不直接触发对红队自身的惩罚；但每次行动的范围、授权、结果必须写入报告并上链留痕。
4. 红队产出（审计报告）可售卖，但**摘要必须公示墙可查**（与"可验证"原则一致），仅完整版付费。

## 2. 测试方法论

每个攻击面按统一模板执行：

```
前提（隔离环境 / 副本来源）
  → 步骤（可复现的操作序列）
    → 预期防御（协议应怎样挡住）
      → 判定：扛住 ✅ / 漏了 ❌ / 部分 ⚠️
        → 严重度（P1–P6，对齐 gzz_enforce PENALTY_MATRIX）
          → 修复建议
```

- **复现要求**：陌生人按本章程可独立复现每一步——这正是 ChatGPT 要求的"杀手级可复现 case"。
- **结果留痕**：每次红队行动产出一条 `Gzz-E-AUDIT-REDTEAM-*` 本地事件（链式哈希），仅存入隔离副本，不污染生产事件簿。
- **周期**：建议每两周一轮，或在大版本（如 MAIP v1.1、API v1.0）发布前必做一轮。

## 3. 审计报告格式（可交付 / 可售卖）

每次行动产出 **《SXJ 红队审计报告 #N》**：

- **公开摘要**（公示墙可查、免费）：范围、攻击面、扛住/漏了的数量、严重度分布。
- **付费完整版**（Builder 档）：每一条的复现步骤、payload 示例、具体修复补丁建议、回归测试命令。

这把"我们尝试攻破 SXJ"转化为**信任证据**——对 prospective Builder 客户而言，比十个宣传页更有说服力。
