四、捆绑码生成规则

捆绑码 = SHA256( Gzz编号 + 事件内容SHA256 + 北京时间戳(ISO8601) + 上一个存根哈希 )

链式结构：每个存根链着上一个存根的哈希。篡改任何一条，后面全部断裂，验证时自动暴露。

六、数据分层策略

层级 存储内容 存放位置 体积估算
存根链 全量存根（永久保留） 本地 万条 ≈ 1.5MB
热数据 近30天事件原文 + 日志 本地 视事件量
温数据 30天以上原文 + 日志 本地压缩包 可配置
冷数据 半年以上事件原文 hygzz.cn 节点 按需拉取
体积结论：存根链极轻，十万条仅 15MB，相当于一张手机照片。本地常驻的始终只有存根链 + 近期热数据，体积可控。无需云数据库。

七、验证路径（无需桌子）

  1. 查存根链 — 本地验证存根哈希是否在链上，确认该存根未被篡改
  2. 对日志 — 核对事件时间戳、编号、操作记录是否一致
  3. 拉原文（按需） — 从热/温/冷数据层拉取事件原文，重新计算 SHA256 对账
  4. 验证通过 — 三条全部对上，即确认事件真实、未被篡改

全程无需回到桌子。存根链是验证的钥匙，原文和日志是验证的素材——钥匙随身，素材按需取。

八、节点同步

本地 存根链权威源 + 热/温数据 核心
hygzz.cn 冷数据备份节点，存归档事件原文 备份
其他节点 可扩展的分布式备份节点 扩展

节点之间互相备份，但存根链的权威始终在本地。节点不存存根链，只存归档的事件原文。即使所有节点离线，本地仍可独立完成验证。
