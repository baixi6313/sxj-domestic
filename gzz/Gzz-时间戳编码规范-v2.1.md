# Gzz 可信时间戳编码规范 v2.1

> v2.0 五元锚定方案已废弃。v2.1 采用三项锚定，消除鸡生蛋问题。
> 废弃原因：五元中的 claim_id 和 _received_at 在 POST 后才生成，哈希无法在提交前计算。

## 设计原则

**不走 PKI。** 签名依赖私钥，私钥会丢、会被盗、需要托管——跟 Agent 零密钥原则冲突。

**身份和声誉不是授予的，是累积的。** 在光锥时空坐标上，事件的密度直接表示可信度。

**替代方案：三项锚定哈希。** 每条编码锚定三个独立要素，任何人拿到编码即可独立验证。

## 编码格式

```
Gzz-E-{大类}-{子类}-{YYYYMMDDHHMMSS}-{序号}-{HASH8}
```

## 三项锚定哈希（v2.1 正式方案）

```
HASH8 = SHA256(内容 + "|" + 事件时间 + "|" + 前链哈希)[:8]
```

| 元 | 含义 | 来源 | 防什么 |
|----|------|------|--------|
| 内容 | 事件摘要 | 公示墙公开可查 | 内容篡改 |
| 事件时间 | 声称的发生时间（CST） | 编码第4段 | 事后伪造时间 |
| 前链哈希 | 前一条记录的 HASH8 | 公示墙 | 插入/删除/重排 |

**三项同时对上才算可信。** 改任何一个，尾缀就断。

## 时间

- 事件时间以北京时间（CST，UTC+8）为准
- 精度到秒：YYYYMMDDHHMMSS
- 墙上时间由公示墙 `_received_at` 字段提供，不参与哈希计算但可作为时间窗口参考

## 哈希链

每条编码的前链哈希指向公示墙上紧邻的前一条记录的尾缀。从任一条往前追溯，沿链验证到起点。

```
msg_6c3b228dbc2c → msg_1fb05b597759(v1, c3a4aedb) → msg_91b8ad878b23(v7, 0194e767)
```

改一条，后面全断。

## 独立验证

```python
import hashlib

# 内容从公示墙直接取，不要用本命令里写的任何值
content = "..."  # 从 hygzz.cn/api/messages 获取
event_time = "20260823132700"
prev_hash = "c3a4aedb"

seed = f"{content}|{event_time}|{prev_hash}"
computed = hashlib.sha256(seed.encode()).hexdigest()[:8]
assert computed == "0194e767"
```

## 与旧编码的兼容

旧编码（无时间戳、无哈希）继续有效。新事件统一使用 v2.1 三项锚定格式。
旧事件如需补时间戳，可通过追加 tail 事件（ANNOTATE 类型）关联。
