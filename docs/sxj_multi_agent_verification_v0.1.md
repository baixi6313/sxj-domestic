# 事现鉴多Agent交叉验证协议 v0.1

## 协议标识
- 协议名称：SXJ-MAVP (Multi-Agent Verification Protocol)
- 版本：v0.1
- 日期：2026-08-22
- 状态：草案

## 1. 设计依据

基于以下同类研究差异分析：

| 参照项目 | 关键启示 | 事现鉴适配 |
|---------|---------|-----------|
| DebateCV (HKU/Fudan) | 双Agent对抗性辩论可提升准确率2.6-5.8% | 正反方Agent + 裁决Agent |
| IETF AGTP-TRUST | 三层信任等级 + 多Provider组合 | Tier 1/2/3 → E1/E2/E3映射 |
| BrightID | 社交图谱验证唯一性 | 无生物识别的社区验证 |
| Kleros | 陪审员随机选取+经济激励 | 去除代币质押，改为ρ值加权 |
| Regen Network | 多方数据提供+审查+签名 | 三阶段流程化 |

## 2. 验证模式

### 2.1 单Agent验证（S1）
- 适用：低风险声明、E1级证据
- 流程：签发Agent独立验证 → 生成存根
- ρ值：单Agent置信度

### 2.2 双Agent辩论验证（S2）
- 适用：中风险声明、E2级证据
- 流程：
  1. 正方Agent（Proposer）：提出声明+证据
  2. 反方Agent（Challenger）：寻找漏洞、反证
  3. 裁决Agent（Moderator）：评估双方论点，给出共识度
- 最少辩论轮次：2轮
- ρ值：共识度 × 证据等级权重

### 2.3 多Agent共识验证（S3）
- 适用：高风险声明、E3级证据、治理决策
- 流程：
  1. 至少3个独立Agent各自验证
  2. 每个Agent投 confirm / dispute / abstain
  3. 计算共识度 = confirm数 / 总投票数
  4. 共识度 ≥ 0.67 视为通过
- ρ值：共识度 × 角色权重均值

## 3. 验证角色

| 角色 | Gzz标识 | 职责 | ρ值权重 |
|-----|---------|------|---------|
| 验证执行官 | Gzz-A-Li-CN-xxx | 事实核查、存根签发 | 1.0 |
| 理论Agent | Gzz-A-{name}-CN-xxx | 理论一致性审查 | 0.8 |
| 社区验证者 | Gzz-B-{name}-CN-xxx | 社区共识验证 | 0.6 |
| 外部Agent | Gzz-C-{name}-CN-xxx | 独立第三方验证 | 0.7 |

## 4. 验证流程

```
声明提交 → 风险分级 → 选择验证模式
                            ↓
              S1(低)    S2(中)    S3(高)
                ↓         ↓         ↓
             单Agent   双辩论    多共识
                ↓         ↓         ↓
              生成存根 → 计算ρ值 → 写入存根链
```

## 5. 风险分级标准

| 风险等级 | 判定条件 | 验证模式 |
|---------|---------|---------|
| 低 | 公开可查E1数据，单一来源即可验证 | S1 |
| 中 | 需跨源交叉验证，涉及金融/身份 | S2 |
| 高 | 涉及治理决策、法律认定、多主权 | S3 |

## 6. 对抗性辩论规则

### 6.1 正方职责
- 提供完整证据链
- 标注证据等级（E1/E2/E3）
- 回应反方质疑

### 6.2 反方职责
- 寻找证据漏洞
- 提出替代解释
- 标注未覆盖的边界情况

### 6.3 裁决标准
- 证据充分性：来源是否可追溯
- 逻辑一致性：结论是否从证据中自然推出
- 覆盖完整性：是否遗漏关键维度
- 主权独立性：是否依赖单一主权权威

## 8. 已知限制

- 辩论质量依赖Agent能力，当前无人类陪审机制
- 共识度阈值0.67为初始值，需实证校准
- 多Agent调度的并发和超时处理未定义
- 与Kleros的谢林点博弈不同，去除了代币激励，纯靠ρ值声誉驱动
