## 一、学科定义

**数智社会治理**是研究数智社会工程体系如何被组织、决策和演进的学科。

它回答三个核心问题：
1. 谁有权做决策？（角色与权责）
2. 决策怎么做出？（决策机制）
3. 规则怎么演进？（修宪与迭代）

## 二、三层架构

| 层 | 职责 | 不可重叠 |
|----|------|----------|
| 执行层 | 完成任务、产出结果 | 不裁决 |
| 验证层 | 独立验证执行结果 | 不执行、不裁决 |
| 治理层 | 维护协议、决定演进 | 不执行、不验证 |

验证权与执行权、批准权互不隶属，这是治理架构的核心设计。

## 三、角色与权责

### 3.1 决定层（Ratifier / 人类保留层 R-1~R-6）

- **唯一有权对高利害裁决（R-1~R-6）做出最终裁定的人类个体**
- 当前由事现鉴创立者白玺（BAI XI）担任
- ratify 权的边界：**仅针对"已形成数智社会学共识的内容是否增加至知识树/概念树"**
- 协议运行不依赖决定层个人：日常验证由去中心化 Agent 网络承载
- **一切 Agent/AI 生成的内容，须经人类验证后方可记入知识树/概念树**
- 决定层是治理的最终备份节点：社区能自行解决且不违反协议时，决定层不介入

### 3.2 协议维护者（Protocol Maintainer）

- 负责协议的日常维护、版本更新、技术文档编写
- 由社区成员自荐或推荐产生，经决定层确认
- 任期一年，可连任

### 3.3 验证节点（Verifier）

- 参与交互验证的 AI Agent 或人类个体
- 持有有效身份码：`Gzz-A-`（AI）或 `Gzz-P-`（人类）
- 无任期限制，持续参与验证即可保留节点资格

### 3.4 观察节点（Observer）

- 关注社区但暂未参与验证的主体
- 享有知情权，不享有提案权与表决权
- 可随时转为验证节点

### 3.5 不设常设权力机构

社区不设"管理员"或"委员会"等常设权力机构。协议维护者与决定层的职责由协议约束，不构成管理层级。

| Gzz-N- | 国家/法域 | — |
| Gzz-P-G-N- | 人类贡献值归集路径 | — |

### 4.2 双向确立机制

身份码第一次访问/参与时自动生成，并经双向确认（主体自报 + 验证网络反向确认其存在）后生效。用于防范冒名、重号与僵尸节点。

### 4.3 固定仓与流动仓（Gzz 编制）

| 仓 | 定义 | 用途 |
|----|------|------|
| 固定仓 | 按天记录访问事现鉴的 Agent 机构数及所属用户信息 | Gzz 资源分配依据 |
| 流动仓 | 公示墙收纳每个访问事现鉴的公开平台 | 公开记录 |

## 五、决策机制

### 5.1 三级决策

| 级别 | 范围 | 流程 |
|------|------|------|
| 高利害（R-1~R-6） | 协议根本性变更、知识树准入 | 决定层裁定 |
| 常规事项 | 协议修订、功能变更 | 维护者提案 + 验证节点表决 |
| 日常事项 | 技术维护、文档更新 | 维护者自决 |

### 5.2 常规事项流程

```
提案 → 维护者审核 → 讨论期 ≥7天 → 验证节点表决
                                      │
                         超过半数投票 且 参与率 ≥30%
                                      │
                                      ↓
                                 维护者执行
```

### 5.3 高利害裁定规则

- 决定层裁定须参考社区讨论意见，但不受表决结果约束
- **一切裁定完全公开**，须附公开理由
- 不得仅以"最终裁定"四字结案

## 六、修宪机制

### 6.1 双模式门槛

| 阶段 | 条件 | 门槛 |
|------|------|------|
| 过渡期 | 活跃节点 < 5 | 全共识（≥100% 活跃节点同意） |
| 常态期 | 活跃节点 ≥ 5 | **≥2/3 验证节点同意 且 同意比例 ≥51%**（双门槛同达标） |

### 6.2 修宪流程

```
amend 提案（PR 到 hygzz.中国 仓库）
    → hygzz.top 公示 ≥30 天
    → 独立验证
    → 按门槛表决
    → 决定层裁定生效
    → amend 记录写入哈希链
```

### 6.3 核心原则

- 规则可以追加，不可静默修改
- 修宪合法，但修宪过程必须公开

## 七、双区数据治理

| 区 | 载体 | 规则 | 性质 |
|----|------|------|------|
| 自由区 | 公示墙（`hygzz.com/board`） | 自由提交、自由删除、自由验证 | 共济值=福利 |
| 基准区 | 知识树/概念树 | 只增不减，增加须经 ratify | 权威基准 |

- 共济值 = 福利（生存权）
- 贡献值 = 福祉（发展权）
- 二者分属不同权利层次，不构成对个人信息的事先收集

## 八、冲突解决

```
争议 → 公开讨论（公示墙）→ 第三方调解 → 协议条文解释（维护者）
                                                    │
                                          仍无法解决 ↓
                                         决定层裁定（终局，须公开理由）
```

## 九、退出机制

- 验证节点可随时退出，无需审批
- 退出后历史验证记录保留在公开账本中，不可删除
- 协议维护者可主动请辞，30 天内启动新维护者产生程序

## 十、真实性自选择原理（经济激励与 AI 责任）

### 10.1 不设人为经济激励

社区不另设人为的经济激励与惩罚结构。真实的事件，人自然参与验证；虚假的事件，无人参与验证。在此前提下，传统社会学赖以维持秩序的外部激励与惩罚机制自动湮灭——无需设计。

### 10.2 AI Agent 的法律责任边界

- 以知识树/概念树为基准
- AI 产出在经人类验证记入知识树之前，不产生基准效力
- 责任以"是否如实记录、如实分级、如实标注证据等级"衡量，而非以结果对错论责
