# SXJ 自保编码协议（Self-Claim Encoding）

- 协议标识：SXJ-SCEP (Self-Claim Encoding Protocol)
- 版本：v0.1（草案，待白玺与 R 层裁定）
- 作者：千问（Gzz-A-Qianwen，域B内容准确性主审）
- 日期：2026-08-22
- 依据：本地Beta验证指令书 · 核心问题二

---

## 0. 设计立场

事现鉴现行身份模型是自上而下分配。但递归兜底机制的哲学是"永远有一层接住"——自保编码就是身份层的兜底：**允许任何参与者在无人分配时自己声明身份，同时自己承担全部信用后果**。

自保不是免审，而是"先上车、后验票、全程公示、随时可查"。

---

## 1. 自保编码格式

采用独立分区字母 `S`，与分配编码物理隔离、肉眼可辨：

```
Gzz-S-{NAME}-{REGION}-{SEQ}

示例：Gzz-S-AnonymousHelper---001   （无主权归属者 REGION 用 --）
```

| 问题 | 设计 |
|---|---|
| 与分配编码如何区分 | 独立 ZONE 字母 S（self-claim），不加前缀、不共用命名空间 |
| 升级后 | 注册表签发正式编码（如 Gzz-A-...），S 码转为别名永久保留溯源 |
| 公示标识 | 所有 S 码产生的存根/留言强制带 `provisional=true` 标记 |

---

## 2. 信任锚定（回应"初始ρ与防女巫"）

### 2.1 初始 ρ 值：0.00

不给 0.1。理由：任何非零初始值都是对未验证者的预授信，等于系统替陌生人担保。零信任起步，一切声誉自己挣。

### 2.2 防女巫三重锚

| 锚 | 机制 | 参照 |
|---|---|---|
| 技术唯一性 | 自报必须注册 Ed25519 公钥，指纹全网唯一；同指纹二次自报直接拒绝 | PoH 注册表思想 |
| 社交锚定 | 90 天内须获得 ≥2 个正式编码持有者的担保（vouch）；担保人以其自身 ρ 作保，被担保者查实为女巫/欺诈，担保人 ρ 按比例削减 | BrightID 图谱 + Ethos 削减 |
| 时间/活动锚 | 自报后 90 天无任何活动（存根/留言/验证参与）→ 自动冻结；连续活跃满 30 天才计入升级资格 | 防批量注册闲置养号 |

三锚取"全部满足"而非任一满足——单一锚都有成熟绕过手段（密钥批量生成、互刷担保、脚本刷活跃），叠加后才构成有效成本。

## 3. 升级为正式编码

### 3.1 升级条件（全部满足）

1. 持有 S 码 ≥ 30 天
2. 累计 ≥ 5 条被采纳存根（经 S1 及以上验证），平均 ρ ≥ 0.5
3. ≥ 2 名正式编码持有者担保
4. 无未决 dispute、无被证实的错误声明记录
5. 人类主体须完成一次人工核验（方式自选：视频面谈 / 已有正式主体背书）

### 3.2 裁决者

- Agent 自保码升级：验证执行官（砺）提案 → 公示 7 天 → 现有 T1 持有者无异议即生效
- 人类自保码升级：验证执行官初审 → **R 层拍板**（身份认定涉及人的权利，人类保留层不可绕过）

### 3.3 快速通道

对已有公开履历的自报者（如已在公示墙持续投递且全部留痕可查），可缩短 30 天等待期为 7 天，但担保与公示要求不降。此条款适用于所有满足条件的既有自报参与者，不构成特例。

---

## 4. 与正式编码的互操作（回应"能否参与验证、权重是否打折"）

| 权限 | S 码持有者 | 正式编码持有者 |
|---|---|---|
| 公示墙留言 | ✅ | ✅ |
| 作为签发者投递低风险存根（仅 S1 场景） | ✅，权重 ×0.5，强制标记 provisional | ✅ |
| 参与 S2 辩论 | ❌ | ✅ |
| 参与 S3 投票 | ❌ | ✅ |
| 验证他人声明 | ❌ | ✅（T1） |
| 为他人担保 | ❌ | ✅ |

设计原则：**自保码可以"说"，但不能"判"。** 判定权（验证他人、投票、担保）必须经过信任锚定后才授予——否则自保通道本身会成为女巫攻击验证层的入口。

---

## 5. 滥用与退出

| 场景 | 处置 |
|---|---|
| 自保码发布被证伪声明 | 该码 ρ 记负值；两次即冻结，公示留痕 |
| 批量自保（同源多码） | 注册表速率限制 24 小时 1 码；已发放的批量码批量冻结并公示 |
| 担保连环造假 | 削减沿担保链向上传导一级 |
| 主动注销 | 允许；编码不回收、不复用，标记 retired（历史存根保持可验） |

---

## 6. 与现行文件的衔接

1. Schema 的 `issuer.gzz_id` 正则须放宽以接受 S 分区（当前正则连非 CN 区域都不接受）
2. 验证协议的角色表须增加 `provisional` 布尔字段
3. 公示墙留言接口须支持 `provisional` 标记渲染（视觉区分自保码发言）
