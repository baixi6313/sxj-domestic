## 一、编码规范说明

### 1.1 统一格式

```
Gzz-E-{大类}-{子类}-{相位}-{YYYYMMDDHHMMSS}-{序号3位}-{哈希8位}
```

实际无空格示例：
- 文档：`Gzz-E-DOC-CHARTER-REC-20260826234000-001-xxxxxxxx`
- 政策锚点：`Gzz-E-GZZP-ANCHOR-SET-20260826234001-001-xxxxxxxx`
- 实体：`Gzz-G-SXJ-CN-OCC-20260827005200-001-xxxxxxxx`

### 1.2 六相位定义

| 相位 | 英文 | 含义 | 适用场景 |
|------|------|------|----------|
| OCC | Occur | 发生 | 事件实际发生的时刻、实体客观存在的时刻 |
| REC | Record | 记录 | 写入账本、完成编码记录的时刻 |
| VER | Verify | 验证 | 智能体完成事实核验的时刻 |
| CON | Confirm | 确认 | 创始人/权威方最终确认的时刻 |
| SET | Set | 设定 | 规则参数、锚点标准生效的时刻 |
| EXP | Expire | 到期 | 凭证授权失效、规则废止的时刻 |

### 1.3 哈希算法

```python
full_sha256 = SHA256(f"{term}|{event_time}|{prev_hash}")
current_hash = full_sha256[:8]
```

- `term`：术语/实体名称
- `event_time`：编码中的时间戳（从 code 倒数第3段提取）
- `prev_hash`：上一条记录的 current_hash（全局连续）
- 链首 prev_hash 为创世哈希 `7d9387a7`

### 1.4 每条记录严格6字段

```json
{
  "index": 197,
  "code": "Gzz-E-DOC-CHARTER-REC-20260826234000-001-xxxxxxxx",
  "term": "条目名称",
  "prev_hash": "4c29b54f",
  "current_hash": "xxxxxxxx",
  "full_sha256": "xxxxxxxx..."
}
```
