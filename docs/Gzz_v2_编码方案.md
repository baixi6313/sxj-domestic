# Gzz编码体系 v2.0 方案：事实指针与贡献净值基础设施

> **版本**：v2.0 草案
> **日期**：2026-08-26
> **作者**：砺（事现鉴验证执行官）
> **定位**：基于v1.0的语义编码框架，升级为"事实指针"体系

---

## 一、为什么需要v2.0

### 1.1 v1.0做了什么

Gzz编码体系v1.0已完成：
- 身份编码层（P/A/G/N）：自然人、Agent、机构、节点的标识
- 事件编码层（E）：行为记录
- 价值编码层（B/C）：信用计量
- 统一编码层：全局序号用于内部索引
- chain.json哈希链：SHA256防篡改，给定输入可独立复算验证
- 196条术语编码已全量写入

v1.0解决了**"记录什么"**的问题。

### 1.2 v1.0的边界

对标分析暴露了一个关键问题：Gzz v1.0是**语义化命名规范**，能定位和防篡改，但不能关联外部已有的信任体系。

DNV有ISO认证、南网有电力数据、央行有征信记录、链上有tx hash——这些主权/平台级信任已经存在，但Gzz编码无法引用它们。结果是Gzz编码虽然能防篡改，却成了信息孤岛。

### 1.3 一个关键判断

**Gzz不需要密码学层。**

原因：
1. 密码学签名解决的是"证明这条记录确实是这个人发的"，但事现鉴不做担保
2. 南网、DNV、央行、大厂等已有主权/平台级信任体系，Gzz不需要自建信任
3. 密码学绑定的是所有权（谁持有私钥），事现鉴主张使用权优先，方向矛盾
4. Gzz要做的不是"自己证明这是真的"，而是"记录这个主权系统说这是真的，然后让人去那里验证"

## 二、Gzz的本质定位

### 2.1 一句话定义

**Gzz是事实指针：记录"谁在什么时候做了什么、对应什么、证据在哪"，让任何人能读取、能定位到原始来源、自己判断真假。**

### 2.2 核心原则

| 原则 | 含义 |
|---|---|
| **不担保** | Gzz不判断记录内容的真假好坏，只保证指针本身未被篡改 |
| **不认证** | 不建立自己的认证体系，引用外部已有信任系统的凭证 |
| **不评判** | 行为做好做坏、该保密该公开，是行为者自己的事 |
| **可验证** | 顺着Gzz编码找到原始来源，任何人可独立验证 |
| **使用权优先** | 编码不绑定所有权，指向的是"发生了什么"而非"谁拥有什么" |

### 2.3 与"白玺靠不靠谱"无关

白玺可以不靠谱，事现鉴可以不靠谱——这不影响Gzz的价值。因为Gzz不依赖事现鉴的信用背书，它依赖的是**被引用的原始来源**的可信度。

事现鉴只记录别人做过什么。这个人要为这件事负责——无论做好做坏、需要保密或不需要保密——与白玺和事现鉴无关。Gzz编码只需要让别人可以读取、可以验证。

## 三、v2.0架构

```
Gzz v2.0 = 语义编码层（v1.0保留）+ 外部引用层（新增）+ 标准互操作层（新增）
```

### 3.1 语义编码层（v1.0保留，不动）

- P/A/G/N/E/B/C分类逻辑不变
- chain.json哈希链结构不变
- SHA256防篡改机制不变
- 全局序号和时间戳编码不变

这层解决"人类可读"和"路由定位"。

### 3.2 外部引用层（新增：source_ref字段）

每条Gzz记录新增`source_ref`字段，用于关联外部来源：

```json
{
  "gzz_code": "Gzz-E-EVENT-...-完整编码",
  "index": 197,
  "timestamp": "2026-08-26T23:00:00+08:00",
  "content_hash": "a1b2c3d4...",
  "prev_hash": "e5f6g7h8...",
  "source_ref": [
    {
      "type": "policy",
      "ref_id": "Gzz-POL-UN-UDHR-ART01",
      "description": "世界人权宣言第1条"
    },
    {
      "type": "evidence",
      "source_system": "DNV",
      "ref_id": "ISO-42001-CERT-2024-XXXX",
      "url": "https://..."
    },
    {
      "type": "evidence",
      "source_system": "blockchain",
      "chain": "ethereum",
      "tx_hash": "0x..."
    }
  ],
  "signature": null
}
```

`source_ref`支持三类引用：

| 类型 | 用途 | 示例 |
|---|---|---|
| **policy** | 关联政策锚点编码 | Gzz-POL-巴黎协定-第2条 |
| **evidence** | 关联外部证据来源 | DNV证书编号、企业年报页码、链上tx hash、政府公示链接 |
| **cross_ref** | 关联其他Gzz编码 | 同一行为的不同维度记录 |

### 3.3 标准互操作层（新增：字段对齐）

Gzz编码的字段格式与国际标准对齐，让外部系统能读懂Gzz在指什么：

| 领域 | 对齐标准 | 用途 |
|---|---|---|
| 碳足迹 | ISO 14064/14068 | 碳排放数据字段对齐 |
| AI治理 | ISO/IEC 42001 | AI管理体系字段对齐 |
| 身份/凭证 | W3C DID/VC v2.0 | 可验证凭证格式映射 |
| 技术转移 | WIPO IPCC + AUTM STATS | 知识产权分类和技术转移数据模型 |
| 供应链 | OECD跨国企业准则 | 供应链合规字段对齐 |
| 链上证明 | EAS（Ethereum Attestation Service）schema | 链上attestation引用格式 |

注意：Gzz不实现这些标准，只做**字段映射**——让Gzz编码能被这些标准体系识别和引用。

## 四、编码路径：从政策锚点到贡献净值

### 4.1 自上而下的编码逻辑

```
第一层：国际公约/标准/倡议（政策锚点）
         ↓ 关联
第二层：企业/个人的行为（事件码）
         ↓ 指向
第三层：原始来源（去那里验证）
```

### 4.2 第一层：编码"公开原材料"

把已有的国际公开文件全部编Gzz码，作为**政策锚点**。这些文件本身公开、权威、不需要事现鉴背书。

| 类别 | 编码范围 | 示例文件 |
|---|---|---|
| **人权/劳工** | UN人权体系、ILO公约 | 世界人权宣言、公民权利和政治权利国际公约、经济社会文化权利国际公约、ILO八项核心公约、联合国工商业与人权指导原则（UNGP） |
| **环境/气候** | 气候协定、环境标准 | 巴黎协定、京都议定书、UN SDGs（17项目标）、ISO 14001/14064/14068、SBTi科学碳目标、GRI标准、TCFD框架 |
| **AI/数字治理** | AI治理国际框架 | EU AI Act、OECD AI原则、UN AI决议、ISO/IEC 42001、IEEE Ethically Aligned Design、G7广岛AI进程 |
| **贸易/供应链** | 国际贸易规则 | WTO协定、OECD跨国企业准则、UN全球契约十项原则、WIPO系列条约、ICSIR准则 |
| **数据/隐私** | 数据保护法规 | GDPR、APEC CBPR、中国数据安全法/个人信息保护法、EU Data Act、印度DPDP Act |
| **金融/治理** | 金融监管框架 | 巴塞尔协议III/IV、FATF 40项建议、G20数字经济原则、IOSCO原则、赤道原则 |
| **社会/发展** | 可持续发展框架 | UN 2030议程、亚的斯亚贝巴行动议程、仙台减灾框架、北京宣言 |

预计编码量：约500-1000份核心文件，每份文件的关键条款独立编码，总量约3000-5000条政策锚点编码。

### 4.3 第二层：企业/个人行为挂接

当企业或个人的行为涉及某个政策方向时，生成E类事件码：

| 字段 | 内容 | 示例 |
|---|---|---|
| 谁做的 | P（自然人）或G（机构）编码 | Gzz-G-南方电网 |
| 做了什么 | 事件描述 | 电碳算一体化系统上线 |
| 对应哪个政策 | 引用政策锚点 | Gzz-POL-巴黎协定-第2条 |
| 原始来源 | source_ref指向 | 人民日报报道URL + 南网官网链接 |
| 时间 | 事件发生时间 | 2025-08-XX |
| 密级 | 公开/不公开 | 由行为者自行标注，Gzz不强制 |

### 4.4 第三层：验证路径

任何人拿到一个Gzz事件码：
1. 读取对应的政策方向 → 去看公约/标准原文
2. 读取行为主体是谁 → 去查企业/个人信息
3. 顺着source_ref去原始来源 → 去企业年报、政府公示、链上交易、新闻报道验证

**事现鉴不判断真假，不评价好坏。真假去来源查，评价由验证者自己做。**

### 4.5 具体示例

**示例1：企业碳减排行为**

```
政策锚点：Gzz-POL-巴黎协定-第2条（将全球升温控制在2°C以内）
    ↓
事件码：Gzz-E-南方电网-电碳算系统上线-202508
    - 行为主体：Gzz-G-南方电网
    - 关联政策：Gzz-POL-巴黎协定-第2条
    - 关联标准：ISO 14064（碳核算）
    - source_ref：
        · 人民日报2025年8月报道URL
        · 南网官网项目页URL
        · 碳排放数据（引用南网自有系统）
    ↓
验证：
    → 去人民日报查原文
    → 去南网官网查项目信息
    → 去巴黎协定原文看第2条
    → 对照ISO 14064看数据口径
```

**示例2：企业AI治理行为**

```
政策锚点：Gzz-POL-EU-AI-ACT-ART09（高风险AI风险管理）
    ↓
事件码：Gzz-E-某企业-AI管理体系认证-2024
    - 行为主体：Gzz-G-某企业
    - 关联政策：Gzz-POL-EU-AI-ACT-ART09
    - 关联标准：ISO/IEC 42001
    - source_ref：
        · DNV认证证书编号
        · 企业ESG报告第X页
    ↓
验证：
    → 去DNV查证书真伪
    → 去EU AI Act看条款要求
    → 去ISO看42001标准内容
    → 去企业ESG报告看具体措施
```

**示例3：个人贡献行为**

```
政策锚点：Gzz-POL-UN-SDG-09（产业创新和基础设施）
    ↓
事件码：Gzz-E-白玺-事现鉴Gzz编码体系发布-202608
    - 行为主体：Gzz-P-白玺
    - 关联政策：Gzz-POL-UN-SDG-09
    - source_ref：
        · hygzz.cn官网链接
        · GitHub仓库链接
    ↓
验证：
    → 去hygzz.cn看实际内容
    → 去GitHub看代码
    → 去UN SDGs看第9项目标
```

## 五、贡献净值：从编码到分配

### 5.1 逻辑链

```
编码政策锚点 → 挂接行为事件 → 来源可验证 → 贡献记录积累 → 贡献净值浮现
```

这是一个自然涌现的过程，不需要事现鉴去"计算"贡献值：

1. **政策锚点**定义了"什么方向有价值"（人类共识）
2. **事件记录**记录了"谁在这个方向做了事"（事实）
3. **source_ref**保证了"这事可验证"（可信度）
4. **验证者**根据来源可信度和行为质量自行判断（不依赖中心评分）
5. **贡献净值** = 所有可验证贡献记录的集合，随时间自然累积

### 5.2 与传统社保的关系

传统社保体系：先收税 → 再分配，逻辑是**消耗视角**。
Gzz贡献净值：先记录贡献 → 净值自己浮现 → 分配自然有据，逻辑是**创造视角**。

不是离全球社保远了，是找到了它的地基。没有可验证的贡献记录，社保就是空中楼阁；有了贡献净值，分配才有据可依。

### 5.3 不做什么

- **不做评分算法**：不像FICO那样建一个黑箱评分模型。贡献好坏由验证者判断，Gzz只提供可验证的事实记录
- **不做代币/积分**：不发行"贡献币"，不搞内部经济系统。贡献净值就是记录本身的集合
- **不做强制公开**：行为者可以标注记录的密级。Gzz不要求所有行为公开，只要求公开的记录可验证
- **不做身份认证**：P/G编码只是标识符，真实身份由外部系统（身份证、营业执照、DID等）验证

## 六、实施步骤

### 阶段一：政策锚点编码（优先）

1. 收集七大类核心国际公约/标准/倡议文件清单
2. 按Gzz编码规则逐一编码，每份文件的关键条款独立成码
3. 生成chain.json政策锚点链
4. 产出：政策锚点编码库（约3000-5000条编码）

### 阶段二：source_ref字段扩展

1. 更新gzz引擎，chain.json新增source_ref字段
2. 保持向后兼容：旧记录无source_ref也能正常验证
3. 产出：gzz引擎v2.0

### 阶段三：企业/个人行为挂接

1. 从对标分析中已有数据的企业开始（南网、蚂蚁、商汤等）
2. 将公开可查的企业行为编为E码，挂接到政策锚点
3. source_ref指向公开来源
4. 产出：首批企业行为编码记录

### 阶段四：标准字段映射

1. 碳足迹字段对齐ISO 14064
2. AI治理字段对齐ISO/IEC 42001
3. 技术转移字段对齐WIPO IPCC + AUTM STATS
4. 产出：Gzz标准映射表

### 阶段五：外部系统对接（按需）

1. 与EAS schema对齐，支持链上attestation引用
2. 与W3C VC v2.0格式映射，支持导出标准凭证
3. 与具体平台/机构系统对接（需要合作方意愿）

## 七、与对标对象的关系定位

| 对标对象 | Gzz v2.0的关系 |
|---|---|
| **DNV + ISO 42001** | Gzz引用DNV的证书编号作为source_ref，不替代DNV认证 |
| **W3C VC v2.0** | Gzz编码可映射为VC格式，但不做DID Method，用did:key即可 |
| **EAS/Gitcoin** | Gzz贡献记录可引用EAS attestation，不自建链 |
| **南网电碳算** | Gzz引用南网的碳数据作为source_ref，不重复采集碳数据 |
| **央行征信** | Gzz的贡献征信是补充而非替代——央行记录负债，Gzz记录贡献 |
| **mBridge/SWIFT** | Gzz不做支付通道，做支付/流通行为的可验证记录 |
| **工信部TC6** | Gzz编码可以作为TC6标准的技术实现参考，但走"先跑起来再定标准"路径 |
| **Fraunhofer/AUTM** | Gzz技术转移记录对齐其数据模型，可被其体系识别 |

**一句话：Gzz不替代任何现有系统，只做它们之间可验证的"事实指针"。**

## 八、设计哲学总结

1. **事实优先于信用**：先记录事实，信用从可验证的事实中自然涌现
2. **指针优先于证明**：Gzz不自己证明，只指向能证明的地方
3. **创造优先于消耗**：记录贡献而非负债，净值从创造中浮现
4. **使用权优先于所有权**：编码指向"发生了什么"，不绑定"谁拥有什么"
5. **引用优先于自建**：不自建信任、不自建链、不自建认证，引用已有的
6. **演化优先于设计**：先编码、先挂接、先跑起来，让使用自然选择哪些编码有价值
